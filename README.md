# Alpha Decor & Paints — ألفا للديكور والدهانات
> منصة تشطيبات الديكور والدهانات الفاخرة، والمدونة المعمارية الرائدة تحت إشراف **الحضرى محمود**، وتطوير المهندس **Mostafa Taha**.

---

## 1. نبذة عن المشروع (Project Overview)
**ألفا للديكور والدهانات (Alpha Decor & Paints)** هي منصة رقمية متكاملة مخصصة لخدمات المقاولات والتشطيبات الداخلية والخارجية الفاخرة (دهانات الحوائط الحديثة، بديل الرخام، بديل الخشب، الفوم، ورق الحائط ثلاثي الأبعاد، ديكورات الجبس بورد، والتشطيبات الذكية).
تضم المنصة:
- مدونة هندسية متخصصة ومقالات قابلة للأرشفة والزحف (Server-Rendered Crawlable Articles).
- استوديو تفاعلي للألوان وتنسيق الديكورات (Color Studio).
- حاسبة تكاليف الدهانات وتوليد عروض أسعار PDF قابلة للطباعة والتنزيل.
- لوحة إدارة متطورة ومحمية بنظام مصادقة مشفر، مع إدارة كاملة للمشاريع والمقالات ورسائل العملاء والمشتركين.
- طبقة ذكاء اصطناعي موحدة (Unified AI Provider Layer) تدعم **Google Gemini** و **Groq (OpenAI-compatible)** لتوليد محتوى احترافي متناسق وتدقيق الخصوصية ومساعدة الزوار.

## 2. حزمة التقنيات (Tech Stack)
- **Runtime & Engine:** Node.js `>=20.6.0` (مع دعم أصلي لـ ESM وتحميل الوحدات عبر `--import tsx`).
- **Backend Framework:** Express.js 4.21+ مع هندسة مسارات معيارية (Modular Routers).
- **Frontend Architecture:** React 19 SPA مبني بواسطة Vite 6+ مع معالجة وتصيير خادمي للمقالات (SEO SSR Snippets).
- **Styling & Design System:** Tailwind CSS v4 مع خطوط فصحى عربية أصيلة معتمدة (`Cairo`, `Tajawal`, `Almarai`) لمنع التشوه البصري.
- **Database & ORM:** PostgreSQL 18+ (Google Cloud SQL) بالربط الآمن عبر Drizzle ORM ونواة تجمع اتصالات `pg.Pool`.
- **AI Engines:**
  - **Google Gemini API** (@google/genai SDK v2.4+) — النموذج المعتمد: `gemini-2.5-flash`.
  - **Groq API** (OpenAI-compatible HTTPS Client) — النموذج المعتمد: `llama-3.3-70b-versatile` والنموذج السريع: `llama-3.1-8b-instant`.
- **Security & Cryptography:** Bcryptjs، تشفير SHA-256 لتجزئة رموز الجلسات، Cookie-Parser المحمي بخيارات `HttpOnly` و `SameSite=Strict`.
- **Testing & Verification:** جناح اختبارات شامل ومستقل مكتوب بـ TypeScript يتضمن 146 اختباراً مؤتمتاً يغطي كافة جوانب الأمان، وSSRF، وقواعد البيانات، ومنع تكرار الصور (dHash)، والجلسات المشفرة، وتكاملات الذكاء الاصطناعي.

## 5. إعداد قاعدة البيانات والترحيلات (Database & Migrations)
تستخدم المنصة **15 جدولاً تطبيقياً دائماً** في PostgreSQL بالإضافة لجدول ترحيلات Drizzle (`__drizzle_migrations`) ليصبح المجموع 16 جدولاً:
1. `users`: حسابات الإدارة والمصادقة (كلمة مرور مشفرة بـ Bcrypt، أدوار المستخدمين، حالة mustChangePassword).
2. `admin_sessions`: جلسات الإدارة النشطة مع تجزئة SHA-256 للرموز ومهلة انتهاء وتوثيق IP وUser-Agent.
3. `login_rate_limits`: حماية تسجيل الدخول من هجمات التخمين والقوة العمياء عبر قفل مؤقت تصاعدي.
4. `api_rate_limits`: محدد معدل الطلبات الموزع (Distributed Rate Limiter) لمسارات النماذج والرفع والإعجابات عبر الخوادم.
5. `site_settings`: إعدادات الموقع، ترويسات التواصل، وبيانات الهوية والموقع الجغرافي.
6. `articles`: المقالات المعمارية والتدوينات وتصنيفاتها وكلمات السيو المفتاحية والبيانات الجغرافية.
7. `contractor_projects`: معرض الأعمال ومشاريع التشطيب وحسابات المقاولين المحمية.
8. `contact_messages`: رسائل واستفسارات العملاء الواردة من نماذج الموقع مع حماية Honeypot.
9. `uploaded_media`: سجل الملفات والوسائط النقطية المرفوعة بعد الفحص الصارم.
10. `newsletter_subscribers`: مشتركو النشرة البريدية مع رمز إلغاء اشتراك عشوائي وتجزئة SHA-256 آمنة.
11. `social_channels`: قنوات وصفحات النشر المسجلة مع توثيق إذن النشر والخصوصية.
12. `social_dispatch_logs`: سجل عمليات النشر الاجتماعي وحالتها الحقيقية ومعرفاتها الخارجية.
13. `image_usage_logs`: سجل بصمات الصور الإدراكية (dHash 64-bit) لمنع تكرار الصور سياقياً.
14. `auto_publish_locks`: أقفال ذرية موزعة تمنع التنافس (Race Conditions) عبر خوادم Cloud Run.
15. `auto_publish_runs`: سجل دورات النشر ومحاولات التشغيل لضمان عدم التكرار.

### أوامر الترحيل:
```bash
# إنشاء ملفات الترحيل بناءً على التغييرات في المخطط (Schema)
npm run db:generate

# تنفيذ الترحيلات على قاعدة بيانات Cloud SQL / PostgreSQL
npm run db:migrate
```

## 6. معمارية الذكاء الاصطناعي المزدوجة (Gemini + Groq AI Architecture)
تم تصميم طبقة موحدة ذكية في `src/server/aiProvider.ts` تقدم المزايا التالية:
1. **مزود افتراضي موثوق:** يعمل النظام افتراضياً بمزود `gemini` ونموذج `gemini-2.5-flash`.
2. **مزود بديل فائق السرعة:** إمكانية تشغيل أو التحويل التلقائي إلى `groq` عبر نموذج `llama-3.3-70b-versatile` ونموذج `llama-3.1-8b-instant`.
3. **عزل أسماء النماذج ومنع التلوث (No Model Cross-Contamination):** في حال حدوث خطأ أو انقطاع في المزود الرئيسي وتحويل الطلب إلى المزود البديل، يقوم النظام تلقائياً بإعادة مواءمة اسم النموذج مع المزود الهدف، مما يمنع تمرير نموذج خاص بـ Gemini إلى Groq أو العكس.
4. **تطهير الأسرار وحجب المفاتيح (Secrets Redaction):** حجب كافة مفاتيح API من نصوص الأخطاء وسجلات النظام واستبدالها بوسوم آمنة مثل `[REDACTED_GROQ_KEY]` و `[REDACTED_GEMINI_KEY]`.
5. **انضباط المهل والتحكم بالإلغاء (Strict Timeouts with AbortController):** ربط كافة طلبات الذكاء الاصطناعي بمهل زمنية صارمة تنتهي بكتل `finally` لتنظيف الموارد ومنع تعليق خيوط العمل (Event Loop).

## 7. قرار المالك الصارم بشأن النشر التلقائي (Auto-Publish Guardrails)
- **النشر التلقائي معطل بصورة دائمة:** بناءً على القرار الصريح لمالك الموقع **الحضرى محمود**، تم تثبيت `autoPublish.enabled = false` و `autoBroadcastOnPublish = false` بشكل افتراضي ودائم.
- **النشر اليدوي الذكي الموجه:** يمكن للمسؤول المعتمد حصراً من لوحة التحكم إطلاق عمليات التوليد والمراجعة والنشر الفردي، مع تطبيق قفل ذري (`publish_locks`) في PostgreSQL لضمان عدم حدوث تضارب.
- **حماية مسار المجدول:** مسار الويب هوك `/api/cron/auto-publish` محمي بسر `CRON_SECRET`، ويرفض أي طلب غير مصرح برمز `401 Unauthorized`، كما يعيد رمز `200` مع حالة `auto_publish_disabled_by_policy` عند استدعائه بشكل نظامي تأكيداً لسريان القرار.

## 8. خدمة النشرة البريدية (Newsletter Subscription System)
- تم ربط نموذج الاشتراك في التذييل (`Footer.tsx`) بمسار الخادم المباشر `POST /api/newsletter/subscribe`.
- **التحقق الصارم:** فحص البريد الإلكتروني عبر تعبير نمطي معتمد للتأكد من بنيته السليمة.
- **منع التكرار الآمن:** يتم حفظ البريد في جدول `newsletter_subscribers` مع قيد فريد (`UNIQUE`)، مع إشعار المستخدم اللطيف في حال كان مسجلاً بالفعل دون إحداث أخطاء في واجهة المستخدم.
- **إلغاء الاشتراك:** دعم مسار `POST /api/newsletter/unsubscribe` لإلغاء الاشتراك البريدي بمرونة.
- **معدل المحاولات (Rate Limiting):** تقييد عدد محاولات الاشتراك من نفس عنوان IP بحد أقصى 10 محاولات في الدقيقة لمنع الإغراق.

## 9. بوت النشر على شبكات التواصل (Social Bot & Dispatch Policy)
- **تعطيل افتراضي محكم:** يعمل البوت بحالة افتراضية معطلة (`botState.enabled = false`).
- **إلغاء أي نجاح زائف (No Fake Success):** لا يقوم البوت بادعاء نجاح النشر مطلقاً؛ بل يُسجل الحالة الواقعية:
  - `not_configured`: عند غياب مفاتيح المنصة (مثل توكن تيليجرام أو فيسبوك).
  - `failed`: في حال فشل الاتصال بالشبكة أو عدم مطابقة شروط الخصوصية.
  - `skipped_expired_24h`: عند محاولة نشر مقال تم نشره منذ أكثر من 24 ساعة.
  - `published`: يتم تسجيلها فقط عند الحصول على رد نجاح رسمي ومؤكد وموثق بمعرف المنشور الخارجي (`externalPostId`) من الواجهة الرسمية للمنصة.

## 10. سياسة أمان المحتوى والحماية السيبرانية (CSP & AppSec Hardening)
تم تأمين الخادم بترويسات أمان متقدمة متوافقة مع متطلبات الإنتاج:
- **إلغاء النطاقات الشاملة (No Open Wildcards):** تم حذف النطاقات العامة `https://*` و `http://*` تماماً من توجيه `frame-src`.
- **حماية الإطارات ومكافحة الاختطاف (Clickjacking Protection):** تقييد توجيه `frame-ancestors` على النطاقات المعتمدة (`'self'`, `https://*.run.app`, `https://aistudio.google.com`).
- **حظر التنفيذ التقييمي في الإنتاج (Zero unsafe-eval in Production):** إزالة `'unsafe-eval'` تلقائياً من توجيه `script-src` في وضع الإنتاج.
- **تقييد النماذج (form-action):** حصر إرسال النماذج إلى النطاق الذاتي (`'self'`).
- **ترويسات دفاعية إضافية:**
  - `X-Content-Type-Options: nosniff`
  - `X-XSS-Protection: 1; mode=block`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: geolocation=(), camera=(), microphone=()`

## 11. نظام المصادقة وإدارة الجلسات (Authentication & Session Security)
- **حساب المالك المشرف:** مشفر بالكامل بواسطة خوارزمية Bcrypt مع ملح تشفيري قوي؛ لا توجد أي كلمات مرور نصية في الكود المصدري.
- **إدارة الجلسات الدائمة:** تُنشأ الجلسات بقيم عشوائية عالية العشوائية (`crypto.randomBytes(32)`). يُخزن في قاعدة البيانات تجزئة SHA-256 فقط للرمز، بينما يُرسل الرمز إلى متصفح المسؤول عبر كوكيز `HttpOnly; Secure; SameSite=Strict`.
- **حماية القوة العمياء (Brute-Force Rate Limiting):** جدول `login_rate_limits` في PostgreSQL يُسجل محاولات الدخول الفاشلة ويحظر عنوان IP تلقائياً لمدة 15 دقيقة بعد 5 محاولات خاطئة متتالية.

## 12. تحسين محركات البحث والأرشفة (SEO, Social Cards & Indexing)
- **مسار الروبوتات (`/robots.txt`):** يوفر توجيهات واضحة لجميع محركات البحث، مع حظر المسارات الحساسة مثل `/admin` و `/api/`.
- **خريطة الموقع التفاعلية (`/sitemap.xml`):** تُبنى ديناميكياً من قاعدة بيانات PostgreSQL متضمنة كافة المقالات المنشورة وروابطها القابلة للزحف مع تواريخ التحديث.
- **ملف إعلانات جوجل المعتمد (`/ads.txt`):** متوافق مع معايير IAB وموثق دون أي معرفات وهمية.
- **التصيير الخادمي للمقالات (SEO SSR Preview):** المسارات `/article/:slug` تخدم وسوم Meta و Open Graph و Twitter Cards وبيانات Schema.org (Article JSON-LD) مباشرة لمحركات البحث ومنصات التواصل الاجتماعي (Facebook, WhatsApp, Twitter, LinkedIn).

## 15. النسخ الاحتياطي واستعادة البيانات (Backup & Disaster Recovery)
لأخذ نسخة احتياطية من قاعدة بيانات PostgreSQL الإنتاجية:
```bash
# إنشاء نسخة احتياطية مضغوطة
pg_dump -h $SQL_HOST -U $SQL_ADMIN_USER -d $SQL_DB_NAME -F c -b -v -f "alpha_backup_$(date +%Y%m%d_%H%M%S).dump"

# استعادة النسخة الاحتياطية عند الحاجة
pg_restore -h $SQL_HOST -U $SQL_ADMIN_USER -d $SQL_DB_NAME -v "alpha_backup_file.dump"
```
